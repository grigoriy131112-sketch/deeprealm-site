# Deeprealm — сайт РП-чата

Сайт для тёмного фэнтези-РП чата Deeprealm: вся полезная информация о чате, ИИ-Проводник (чат-справочник) и ИИ-Анкетолог для проверки персонажей.

## Возможности

- **Главная** — краткое описание мира и как вступить.
- **Лор** — история мира: Спаситель, Единое Королевство, Великая Битва, Грохот, Кализей, Подземелье.
- **Правила** — все 7 разделов правил чата и система наказаний.
- **Расы** — 5 основных рас, отношения между ними, правила и поля для создания своей расы.
- **Классы** — базовые классы с ресурсами и истощением, специализации, классы игроков, правила баланса.
- **Пасс уровней** — отдельная страница с наградами за уровни 1–15 (Новичок, Продвинутый, Профи).
- **Администрация** — направления команды (зам владельца, пиарщик, модератор, разработчик, гейм-мастер, анкетолог, ивентолог), ступени роста и что спросят на собеседовании.
- **Анкетолог (ИИ)** — диалог с ИИ: свободные вопросы, команда «добавь в анкету» сохраняет детали в черновик, после проверки выдаётся ссылка на чат. На странице можно раскрыть **шаблон заявки на сюжет для ГМ**, а анкетолог поможет оформить заявку по нему.
- **Анкетолог по кандидатам (ИИ)** — отдельный чат для вступления в администрацию. Вопросы идут по порядку и зависят от направления: у модератора — сколько готов активить, у гейм-мастера — как часто готов писать посты, и так далее. Если кандидат задаёт встречный вопрос («а как часто надо приводить людей?»), анкетолог сначала отвечает и только потом продолжает анкету. В конце — заключение и пометка «РЕКОМЕНДОВАН».
- **Проводник (ИИ)** — чат-справочник: отвечает на вопросы о правилах, лоре, расах, классах и вступлении. Без ролевой игры.
- **Переписка сохраняется** — все три чата хранятся в браузере (`localStorage`), переживают перезагрузку страницы. Можно вести несколько чатов на каждый раздел, переключаться между ними, а у каждого сообщения есть копирование, редактирование и удаление.
- **Живая сцена** — на фоне нарисован ночной пейзаж: замок на скале со светящимися окнами и воротами, луна, звёзды, плывущий туман и поднимающиеся угли. Сцена реагирует на движение мыши и прокрутку, но отключается при системной настройке «уменьшить движение».
- Двуязычный интерфейс: **RU / EN**.

## Публичная ссылка (постоянная)

Постоянная ссылка — это адрес хостинга (например
`https://deeprealm-site.onrender.com`). Она **не зависит от песочницы
OpenHands**: сайт продолжает работать, даже когда чат или песочница
приостановлены. Порт задаётся переменной `PORT`.

Адреса вида `*.prod-runtime.all-hands.dev` — это временные песочницы
OpenHands. Они умирают вместе с песочницей и **не** являются сайтом.

### Как включить постоянную ссылку

В репозитории уже есть `Dockerfile` и `render.yaml`, поэтому хостинг
настраивается в пару шагов:

1. Зайти на <https://render.com> и войти через GitHub (кнопка **Sign in with
   GitHub**). Аккаунт GitHub уже есть, отдельная регистрация не нужна.
2. **New → Blueprint**, выбрать репозиторий `deeprealm-site`. Render сам
   прочитает `render.yaml`, соберёт Docker-образ и выдаст постоянный адрес.
3. В настройках сервиса добавить два секрета — их значения Render спросит сам,
   потому что в `render.yaml` они помечены `sync: false`:
   - `LLM_API_KEY` — ключ ИИ (см. «Подключение ИИ» ниже);
   - `GITHUB_TOKEN` — токен с правом записи в этот репозиторий, чтобы
     одобренные расы и классы публиковались на сайте.

   Оба ключа хранятся только в настройках сервиса и никогда не попадают в
   репозиторий и в образ.
4. Дальше любое изменение в `main` публикуется автоматически.
   Альтернатива — Railway, Fly.io: везде нужен тот же `Dockerfile`.

После первого деплоя впишите адрес на главной странице (блок «Как вступить»)
вместо временной ссылки на чат.

### Чтобы ИИ-помощники работали всегда

Важный факт: **бесплатный тариф Render останавливает сервис после 15 минут без
посетителей.** Дальше первый зашедший ждёт 30–60 секунд, пока сервис поднимается.
То же самое на Koyeb (час простоя), у Railway и Fly.io бесплатного тарифа для
работающего сервера уже нет. Поэтому «всегда» достигается одним из двух способов.

**Способ 1 (бесплатно): будильник.** Готовый файл лежит в репозитории как
`deploy/keep-awake.yml`. Он каждые 10 минут заходит на `/healthz`, а любой заход
считается активностью и не даёт сервису заснуть.

1. Скопируйте `deploy/keep-awake.yml` в `.github/workflows/keep-awake.yml` (через
   веб-интерфейс GitHub: **Add file → Create new file**, имя
   `.github/workflows/keep-awake.yml`, вставить содержимое).
2. Откройте GitHub → **Settings → Secrets and variables → Actions → вкладка
   Variables → New repository variable**.
3. Имя: `SITE_URL`, значение: адрес от Render (например
   `https://deeprealm-site.onrender.com`).
4. Готово. Пока переменная не задана, задача просто ничего не делает.

Файл вынесен в `deploy/`, потому что GitHub не принимает workflow-файлы от
токена без права `Workflows`; через веб-интерфейс он добавится без ограничений.

Этот способ держит сервис живым круглосуточно и ничего не стоит. Минус: Render
считает это активностью и может ограничить такой сервис при злоупотреблении
правилами бесплатного тарифа.

**Способ 2 (надёжно): платный тариф.** Render Individual, $7 в месяц, сервис не
останавливается никогда — холодных стартов нет вообще. Это единственный вариант
без оговорок, если сайт нужен как основной.

### Что происходит с одобренными расами и классами

Когда анкетолог одобряет расу или класс, статья сразу уходит в репозиторий
через GitHub API и появляется на сайте. При старте сервис читает статьи из
репозитория обратно, поэтому перезапуск хостинга не теряет ни одной статьи.
Для этого и нужен `GITHUB_TOKEN`.

### Публикация из любой песочницы или чата

Файл `scripts/sync_from_conversation.py` забирает актуальные файлы из любого
чата OpenHands и пушит их в репозиторий — так обновления может присылать и
исходная песочница, и любой другой чат:

```bash
CONV_ID=latest REPO=<owner>/<repo> \
OPENHANDS_API_KEY=... GITHUB_TOKEN=... \
python scripts/sync_from_conversation.py
```

Хостинг увидит новый коммит и сам перевыпустит сайт.

## Подключение ИИ

ИИ-чаты (Проводник и Анкетолог) требуют API-ключ. Упрощённого режима нет: без ключа чаты покажут сообщение, что нужно добавить ключ в `.env`.

Ключ можно получить **бесплатно** (без оплаты) у любого OpenAI-совместимого провайдера:

1. **Google AI Studio (Gemini)** — https://aistudio.google.com/apikey
   ```
   LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
   LLM_MODEL=gemini-flash-latest
   LLM_FALLBACK_MODELS=gemini-3.5-flash,gemini-3.6-flash,gemini-3.7-flash
   ```
   `LLM_FALLBACK_MODELS` необязателен: если основная модель занята (503), сервер автоматически попробует следующую.
2. **Groq** — https://console.groq.com/keys
   ```
   LLM_BASE_URL=https://api.groq.com/openai/v1
   LLM_MODEL=llama-3.3-70b-versatile
   ```
3. **OpenRouter** (есть модели с пометкой `:free`) — https://openrouter.ai/keys
   ```
   LLM_BASE_URL=https://openrouter.ai/api/v1
   LLM_MODEL=meta-llama/llama-3.3-70b-instruct:free
   ```

Дальше скопируйте `.env.example` в `.env`, вставьте ключ в `LLM_API_KEY` и перезапустите сайт.

Ключ используется только на серверной стороне и никогда не попадает в браузер.

## API

| Эндпоинт | Назначение |
| --- | --- |
| `GET /api/knowledge` | Все данные сайта: чат, правила, лор, расы, классы, пасс уровней, администрация |
| `GET /api/chat-link` | Постоянная ссылка на чат, контакт владельца и подпись |
| `POST /api/guide` | ИИ-Проводник: ответы на вопросы о чате |
| `POST /api/interview` | ИИ-Анкетолог: проверка анкеты персонажа |
| `POST /api/staff` | ИИ-Анкетолог по кандидатам: собеседование на вступление в администрацию |
| `POST /api/refresh` | Перечитать блог Deeprealm на новые расы/классы игроков |

## Авто-обновление рас и классов игроков с блога

Игровые расы и классы, которые создают игроки, сайт берёт из блога Deeprealm.
При старте сервер читает страницы-списки, находит новые пункты и сохраняет их
в `data/knowledge.json`, после чего они сразу появляются на сайте.

Источники ссылок задаются в `data/knowledge.json`:
`races.player_blog_link` (расы игроков) и `classes.player_blog_link` (классы игроков).

Когда вы добавите новую статью и допишете её в список на блоге, сайт подхватит
её сам: при следующем запуске или в течение часа. Проверить и обновить вручную:

```bash
curl -X POST http://localhost:12000/api/refresh
```

Периодичность задаётся в `.env` через `BLOG_SYNC_MINUTES` (по умолчанию 60 минут,
`0` — отключить). Если блог недоступен, сайт просто показывает уже сохранённый
список — ошибка не ломает страницу.

## Статьи на сайте

Все статьи блога перенесены на сам сайт: они лежат в `data/articles.json` и
показываются в разделе «Статьи» с поиском и фильтром «Расы / Классы / Прочее».
Ссылка на блог при этом остаётся у каждой статьи — сайт не зависит от того,
доступен ли блог.

Обновить список статей из блога вручную:

```bash
npm run import-articles
```

Когда анкетолог одобряет анкету расы или класса, бот сам оформляет статью и
добавляет её на сайт. Игрок сразу видит в ответе финальную фразу со ссылкой на
раздел «Статьи». Статья игрока получает свой адрес и никогда не затирает
статью из блога с таким же названием.

### Где хранятся статьи

По умолчанию статьи лежат в `data/articles.json` внутри контейнера. На бесплатном
тарифе Render файловая система временная: после передеплоя статьи, созданные ботом,
пропадут, а 45 статей из блога останутся (они в образе). Чтобы статьи игроков
не терялись, подключите постоянный диск и укажите путь к нему:

| Переменная | Что делает |
| --- | --- |
| `ARTICLES_PATH` | Путь к файлу статей на постоянном диске, например `/data/articles.json` |
| `ARTICLES_SEED` | Необязательно: откуда взять 45 статей блога при первом запуске (по умолчанию — копия в образе) |

Если файла по `ARTICLES_PATH` ещё нет, он один раз создаётся из `ARTICLES_SEED`,
поэтому сайт сразу открывается с полным списком статей.

## Деплой и обновления

Сайт деплоится из git-репозитория и **не зависит от песочницы**. Конфигурация
хостинга в `render.yaml` и `Dockerfile`; ключ `LLM_API_KEY` задаётся в панели
хостинга, в репозиторий не попадает.

Обновлять сайт может любой чат или песочница:

```bash
REPO=<владелец>/deeprealm-site CONV_ID=latest \
  python3 scripts/sync_from_conversation.py
```

Скрипт забирает рабочую папку указанного чата (`CONV_ID=latest` — самый свежий),
делает коммит и пушит в `main`. Хостинг сам публикует новую версию. Больше
подробностей — в `AGENTS.md`.

## Архив исходного чата

В `chat-archive/` лежит всё из чата, где создавался сайт:

- `transcript.md` — полная переписка и действия агента;
- `user-provided-data.md` — все данные, которые присылал владелец;
- `site-content.json` — снимок содержимого сайта на момент спасения.

## Структура

```
server.js              Express-сервер и ИИ-эндпоинты (/api/guide, /api/interview, /api/staff, /api/articles)
blog-sync.js           Скрапер списков рас/классов игроков с блога
articles.js            Разбор статей блога (HTML → текст, тип статьи)
scripts/import-articles.js  Перенос всех статей блога в data/articles.json
article-store.js       Хранилище статей: список, чтение, публикация статьи игрока
publish.js             Оформление одобренной анкеты расы/класса в статью
data/knowledge.json    База знаний: правила, лор, расы, классы, шаблон анкеты
data/articles.json     Все статьи сайта: расы, классы, лор, шаблоны
public/                Фронтенд (index.html, styles.css, app.js)
test/                  Тесты (node:test)
scripts/               sync_from_conversation.py — публикация из любого чата
chat-archive/          История и данные исходного чата
Dockerfile             Образ для хостинга
render.yaml            Конфигурация сервиса (авто-деплой при пуше)
deploy/keep-awake.yml  Готовый будильник: не даёт бесплатному хостингу заснуть
```
